# Changelog
This is a simple changelog to keep track of things that have changed. It is not a substitution for upgrade documentation.

## ToDos
These todos should be as temporary as possible:

## v1.3.0
1. Changed - The version migrator (formerly the separate `zubzet/version-migration` repository) now lives in the framework repository under `migrator/`, with its commit history preserved
1. Added - Secrets, encrypted at rest for values that have to be stored and read back, like the credentials of an S3 bucket a customer connects: `encryptSecret()` and `decryptSecret()` (or `ZubZet\Framework\Security\Secrets\Encryption::encryptSecret()` / `decryptSecret()`) use AES-256-GCM with a key derived from the new `encryption_key` setting (at least 32 bytes). Decryption detects a wrong key or a modified value and throws a `ZubZet\Framework\Security\Secrets\DecryptionException`. Encrypted values are URL-safe text of the form `zenc:aes-256-gcm:<base64url>` that name their cipher, so a later default cipher (behind `ZubZet\Framework\Security\Secrets\Cipher\Cipher`) keeps stored values readable. The framework now declares `ext-openssl` in `composer.json`. See [Secrets](docs/core-features/secrets.md). **Migrator note:** set `encryption_key` before using the helpers, preferably via `CONFIG_ENCRYPTION_KEY` with an empty `encryption_key =` kept in `z_settings.ini`, since environment variables only override settings that exist there; values encrypted with it cannot be recovered once it is changed or lost
1. Added - Organization self-management in the Z-Admin panel at `/z/organization`: members with `z.organization.rename` rename their organization, `z.organization.invite` creates invitation links for active accounts outside any organization and `z.organization.roles` gives members the roles released to organizations, `z.organization.manage` shows the sidebar entry and the dashboard card. An invitation is valid for 7 days, an address holds one open invitation per organization, open invitations can be revoked and no mail is involved - the inviter shares the link. The invited user accepts it at `/z/organization/invitation/{token}` and joins the organization including its linked group; every other visitor gets a 404. The page is built from the new `zubzet::organization.*` components and new `Z.Lang` texts. See [Organization Management](docs/z-admin/organization-management.md)
1. Added - Roles and groups can be released to organizations through `z_role.is_org_assignable`, set with a new checkbox on a role's page in the Z-Admin panel. **Migrator note:** nothing is released after the migration, organizations can only hand out roles once you tick it
1. Changed - The role select on the Z-Admin user page offers every role, but a group only while the user already holds it. Groups follow the user's organization and are no longer handed out there
1. Added - Two factor authentication with time based one time passwords (`spomky-labs/otphp`): `$user->startTwoFactor()` stores a secret and returns it with its provisioning uri, `confirmTwoFactor($code)` turns it on, `verifyTwoFactorCode()`, `hasTwoFactor()`, `twoFactorConfirmedAt()` and `disableTwoFactor()` complete the account side. The login of an account with two factor answers with a challenge instead of a session, redeemed with a code at `_zubzet/two-factor/login` - valid for `two_factor_challenge_seconds` (defaults to 600), once, and wrong codes count against the login limit; `Z.Presets.Login` opens the code modal on its own. `$req->requireFreshTwoFactor()` guards an action behind a check within `two_factor_freshness_seconds` (defaults to 900), and `Z.Request` and `Z.Forms` open the modal on a `twoFactorRenew` answer. Sessions keep `last_two_factor` and `remaining_two_factor_tries` (`two_factor_tries`, defaults to 5), an admin can turn two factor off on the user page. See [Two Factor Authentication](docs/core-features/two-factor-authentication.md). **Migrator note:** the modal ships with `<x-zubzet::body/>`, a layout without the body essentials has to render `<x-zubzet::authentication.two-factor/>` itself
1. Added - Profile page at `/z/profile` for every logged in account, without a permission: password change, two factor, sessions and api keys, each renamable and revocable, api keys created with a lifetime from `APIKey::LIFETIMES` or none. The page is built from the `zubzet::account.*` components, which post to `_zubzet/profile/*` and can be placed on any page. See [Profile](docs/z-admin/profile.md)
1. Added - Sessions record when they were last used in `z_logintoken.last_used`, read through `$session->lastUsed()` and written at most once per `session_last_used_throttle_seconds` (defaults to 60), a changed address always. The token column is now indexed
1. Added - `Session::clearForUser(User $user)` ends every login of a user in one statement
1. Changed - `$user->clearSessions()`, and with it `$user->updatePassword()`, no longer invalidates the user's api keys. **Migrator note:** revoke keys through `APIKey::byUser()` where a password change used to end them
1. Added - `$res->error($message, $payload = [])` merges an optional payload into the answer, like `success()` does, and `$res->loginAs()` takes `recordTwoFactor` to stamp a login that verified a code itself
1. Added - Bearer authentication: a request carrying `Authorization: Bearer <token>` is authenticated by that token, session or api key, before the `z_login_token` cookie is looked at. An invalid bearer token is rejected and does not fall back to the cookie; any other scheme is ignored. `$req->bearerToken()` returns the token or `null`. See [Access Control](docs/core-features/access-control.md#bearer-authentication)
1. Added - `$user->checkLoginTries()` returns `false` when the account saw more than `maxLoginTriesPerTimespan` failed logins within `maxLoginTriesTimespan` (and logs `ACCOUNT_LOGIN_RATE_LIMITED`), `$user->recordLoginTry()` counts a failed one. The framework's login uses them. See [Access Control](docs/core-features/access-control.md#login-tries)
1. Changed - Too many failed logins no longer send the "Security alert" email to the account owner; the login is still blocked and logged. **Migrator note:** an application that wants the warning sends it itself when `checkLoginTries()` returns `false`
1. Added - Translations backed by `symfony/translation`: catalogues named `{domain}.{locale}.{format}` (`json`, `php`, `csv` or `ini`) in `app/Translations/`, and in modules and the framework alike, where an application key beats a module key and a module key beats the framework's. `__($id, $parameters, $domain, $locale)` translates; it is only declared when no global `__()` exists yet. The locale comes from the user's `z_user.locale_bcp_47`, then from the best `Accept-Language` entry a catalogue covers (RFC 4647 lookup, needs the `intl` extension), then from the first of `fallback_locales` (defaults to `en`). See [Translations](docs/core-features/translations.md). **Migrator note:** the migration `2026-09-02_user_locale_bcp_47.sql` adds the nullable `z_user.locale_bcp_47`, it runs automatically
1. Added - The admin panel is translated, in English and German, and the form texts of `Z.Lang` (`form.*`) come from the catalogue, so an application translates or redefines them like its own texts
1. Added - `$req->acceptLanguage()` returns the locales of the `Accept-Language` header, best first, with malformed entries and `q=0` dropped. See [Parameter Abstraction](docs/core-features/parameter-abstraction.md#accept-language)
1. Added - A fixed session expiry: `z_logintoken` gained `expires_at`, set through `$session->setExpiresAt(?DateTime $expiresAt)` and dropped again by passing `null`. It takes priority over the computed lifetime, so while one is set neither `loginTimeoutSeconds` nor `extended_seconds` moves the point a session dies - `expiresAt()` and `isExpired()` report the fixed date instead. A session exempt from expiring still outranks it, because it is taken out of expiring altogether rather than expiring at another point. See [Access Control](docs/core-features/access-control.md#lifetime-management)
1. Added - UUIDs on authentication objects: `z_user`, `z_role`, `z_organization`, `z_logintoken` and `z_file` gained a `uuid` column, `NOT NULL` with a unique index. Every object retrievable by id is now also retrievable by uuid (`User::byUuid()`, `User::byUuids()`, and the same on `Role`, `Group`, `Organization`, `Session` and `APIKey`); `$user->uuid()` and `user()->uuid` expose it. Use it as the identifier handed out in URLs and REST payloads, the numeric id stays the internal key. For a session or an api key the uuid is the **only** identifier safe to hand out - the token authenticates whoever presents it - and `byUuid()` is scoped like `byId()`, so `Session::byUuid()` does not find a key and `APIKey::byUuid()` does not find a login. See [Access Control](docs/core-features/access-control.md#uuids)
1. Changed - The minimum database server is now **MariaDB 11.7**. **Migrator note:** upgrade the server before applying this release's migrations, see [Migrating from v1.2.0 to v1.3.0](docs/setup/upgrade/1.2.0-to-1.3.0.md)
1. Added - API keys: `z_logintoken` gained `name`, `is_permanent` and `is_apikey`. A session can now be named (`setName()`, `name()`) and exempted from expiring (`setCanExpire(false)`, `canExpire()`) - an exempt session never expires, `expiresAt()` returns `null` for it and it is never invalidated on use. The exemption is stored inverted, in the `is_permanent` column. The new `APIKey` object represents rows carrying the api key flag; it is a **sibling** of `Session`, not a subclass, because a key belongs to one user and its `APIKey::add(User $user, ?string $name = null)` takes no `$userExec`. They share their behavior through the new `CanUseSession` trait; `byToken()` returns `Session|APIKey|null`, so type as `Session|APIKey` where either kind may appear. Every retriever is scoped to the class it is called on (`Session::byUser()`/`byId()` list logins, `APIKey::byUser()`/`byId()` keys, the way `Role` and `Group` split `z_role`); `byToken()` is the exception and resolves both kinds, because authenticating a request must not care which kind the token is. See [Access Control](docs/core-features/access-control.md#api-keys)
1. Changed - Issued session tokens are now `zub-` plus 32 random bytes in hex (68 characters, previously 40 without a prefix). Tokens already in the database keep working, only newly issued ones carry the new format; the `token` column is `VARCHAR(255)` and unchanged. **Migrator note:** anything that stores, forwards or validates a token by its length has to be widened
1. Added - Sessions record where they come from: `z_logintoken` gained `device` (the user agent, cut to 255 characters), `reason` (why the session was created, e.g. an impersonation), `ip_creation` (the address it was created from) and `ip_last` (the address it was last used from, rewritten only when a request arrives from a different one). `device` and both addresses are filled automatically on every path that hands out a token; `$name` and `$reason` are chosen by the caller through `Session::add()`, `APIKey::add()` and `$res->loginAs()`. The z-admin "Login as" button asks for a reason and falls back to `z-admin impersonation` when none is given, cutting an overlong one to what the column takes
1. Changed - `$res->loginAs()` no longer names a session after the user agent - that is what `device` is for, and `name` now stays `NULL` until someone chooses one. **Migrator note:** sessions named by the previous behaviour keep the user agent as their `name`; the schema migration runs automatically
1. Added - Organization management in the Z-Admin panel: create organizations with an optional permission group, list, rename and delete them, and assign users to one on Add User and Edit User. Guarded by the new permissions `admin.organizations.list`, `admin.organizations.edit`, `admin.organizations.delete` and `admin.organizations.create`. Deleting an organization detaches its members and deactivates its linked group
1. Changed - `web/Z.js` renders select option texts and multi-select badges as text (`textContent`) instead of HTML, and `Controller::makeFood()` encodes `<`, `>` and `&` (and quotes as before) via `JSON_HEX_TAG | JSON_HEX_AMP`. **Migrator note:** applications that put HTML entities or markup into food texts (e.g. `&nbsp;` indents, pre-escaped `&amp;`, icons) now see them literally and should pass plain text instead
1. Added CSRF protection: every request other than `GET` / `HEAD` / `OPTIONS` that a browser could send cross-site must return the host-only `z_csrf` cookie as an `X-CSRF-Token` header or a `_csrf` form field, otherwise it is answered with 403. Requests with a non-form `Content-Type` (e.g. JSON) or an `Authorization` header other than `Basic` / `Digest` / `NTLM` / `Negotiate` are skipped, since a browser cannot send them cross-site without a CORS preflight; routes and groups opt out with `->withoutCsrf()`. The cookie is `Secure` whenever the `host` setting is `https://`. **Migrator note:** `Z.Forms` / `Z.Request` attach the header themselves; a raw `<form method="post">` must embed `CSRF::field()`, custom form-encoded `fetch()` / `$.ajax()` posts must send `Z.Request.csrfToken()` as `X-CSRF-Token`, and endpoints that authenticate without the session cookie (form-encoded API keys, `navigator.sendBeacon()`) need `->withoutCsrf()`. The login runs only for a post with `action=login` now, a post with just `name` and `password` is answered with the login page, so custom login forms and scripts have to send the field. The bundled forgot password page redirects to `/login` after the request without the "email sent" alert
1. Changed the `z_login_token` session cookie and the maintenance bypass cookie to carry `Secure` and `SameSite=Lax`. `Secure` is derived from the `host` setting, like for the CSRF cookie. **Migrator note:** a deployment whose `host` says `https://` but is actually served over plain HTTP loses its logins until `host` matches the real scheme, and a cross-site `POST` that returns to the application (OIDC `form_post`, SAML, payment returns) arrives without the session cookie, as does any request from a cross-site iframe, where `z_csrf` is not stored either
1. Added `Z.Request.csrfToken()`, which reads the `z_csrf` cookie so custom `fetch()` / `$.ajax()` calls can attach the `X-CSRF-Token` header without parsing `document.cookie` themselves
1. Changed `/z/login_as/{id}` in the Z-Admin panel to answer only a post with `action=login_as` and to return `{"result": "success"}` instead of redirecting; a `GET` is answered with 405, since a link on another site could otherwise switch an admin to another user. The "Login as" button on the user page posts it through `Z.Request.root()`. **Migrator note:** a link or script that opens `z/login_as/{id}` has to post `action=login_as` with the CSRF token
1. Added #183 - Multiple forms in one view: every `ZForm` submission carries a `formAction` taken from the new `name` option (falling back to `dom`), and `$req->hasFormData($formAction)` targets a single form. Argument-less calls keep detecting any submitted form
1. Added #178 - Health endpoint at `GET /_zubzet/health`: performs an explicit database check and reports plain JSON without error details. Enabled by default, disable via `health_endpoint_enabled = false`

1. Added #80 - Cluster-resilient database connection: `Connection::exec()` retries transient contention errors (deadlock, lock-wait timeout, Galera serialization conflict) and recovers dropped connections, including Galera nodes refusing service as SST/IST donor (`1047`), by reconnecting through the endpoint, re-preparing, and re-running the statement. Tunable via `db_max_retries` (default `3`, `0` disables). **Migrator note:** a statement that previously failed on a dropped connection may now be applied twice in the rare case where the server executed a write but the acknowledgment was lost; single statements only, since every `exec()` auto-commits

Added - Encrypted database transport: `db_ssl = true` connects over TLS and verifies the server certificate against the system trust store; a private authority is added to that store or set via `openssl.cafile`. Applies to migrations as well. Documented in [Database Connection](docs/core-features/database-connection.md)
1. Added - Optional persistent database connections via `db_persistent = true`: the PHP worker keeps the connection open across requests and skips the handshake. Off by default, because a worker then stays on the cluster node it first reached. **Migrator note:** mysqli pools by endpoint and credentials, not by transport, so reload PHP-FPM when changing `db_ssl` with this on

Added - Module system: Composer packages of type `zubzet-module` contribute controllers, models, views, routes, console commands, migrations, seeds, and webroot assets, resolved through the new central `Registry` (`src/Registry`) with the precedence userspace, then modules (ordered by the `modules` ini key, then Composer installed order), then framework. Fixed - A `showErrors` value that is not one of `0`, `1` or `2` (an empty string, a word, `7`) stopped the bootstrap with a `TypeError`, followed by a second fatal from the slow-request logger, which also ran when the request never existed. Fixed - With a non-empty `rootDirectory`, `rootFolder` and `root` (and with them `$opt["root"]`, `$opt["absRoot"]`, `$req->getRootFolder()`, `$req->getRoot()` and `Z.Request.rootPath`) ended without a slash, so every link appended to them broke, e.g. `/sublogin/verify`. They now always end with a slash. **Migrator note:** application code that added its own slash after these values (`$opt["root"] . "/path"`, `rerouteUrl("/path")`, `Z.Request.root("/path", …)`) now produces a double slash; the router and `getUrlParts()` answer `/sub//path` like `/sub/path`, so such links keep working, but the slash should be dropped. Such code only worked with `rootDirectory = sub` written without a trailing slash on v1.2.x: with an empty `rootDirectory` it produced `//path`, and before v1.2.0 the value was used verbatim, so `rootDirectory = sub/` was the working setup and yields the same values again. Fixed - Routes defined with `Route::` (including the asset proxy and `/_zubzet/health`) never matched when the application ran below a non-empty `rootDirectory`, because the router compared them against the full request path. The root directory is now stripped first, like the autorouter already did

1. Fixed - Route and group middleware could be skipped by spelling the path differently. Fixed - An upload field that accepted the `php` extension let anyone run code on the server: uploads land in `webroot/uploads/`, the `uploadFolder` of the project template and of migrated projects, and Apache ran an uploaded `.php` file when its URL was opened. Fixed #238 - An autocomplete field with an endpoint as `autocompleteData` showed an answer only on the next keystroke, so the suggestions for the last typed term never appeared, and of several answers in flight it kept the first to arrive instead of the one for the latest term. Fixed #184 - Tables with different collations made the permission lookup fail with "Illegal mix of collations for operation 'UNION'": the bundled migrations took the database default, and `z_migration_lock` / `z_version` were created as `utf8mb3_unicode_ci` by Doctrine. See [Views](docs/core-features/views.md)
