## New Features

### UUIDs on authentication objects

Users, roles, groups, organizations, sessions and api keys (and the `z_file` table) carry a **UUID**
next to their numeric ID. It is the identifier meant to leave the application - URLs, REST payloads,
anything handed to a third party - because it does not reveal how many records exist and cannot be
guessed by counting up. The numeric ID stays the internal key.

Every object that can be retrieved by ID can also be retrieved by UUID, and every object exposes
its own:

```php
$user = User::byUuid($uuid);
$roles = Role::byUuids(...$uuids);

user()->uuid;
$user->uuid();
$organization->uuid();
```

For a session or an api key the UUID is the only identifier safe to publish - the token
authenticates whoever presents it, so it belongs in a cookie or an `Authorization` header and
nowhere else. Use the UUID to address a session in a "your active sessions" list:

```php
$session = Session::byUuid($uuid); // scoped like byId(): never returns an api key
$key = APIKey::byUuid($uuid);
```

See [Access Control](../../core-features/access-control.md#uuids) for the full API.


## Requirements

### MariaDB 11.7 or newer

v1.4.0 raises the minimum database server to **MariaDB 11.7**. Older servers are no longer supported.

ZubZet targets **MariaDB**, not MySQL: the framework-bundled migrations use MariaDB-only syntax
(`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`), which MySQL rejects. The development stack and the
e2e suite run **MariaDB 11.8**.

Check what your server runs:

```sql
SELECT VERSION();
```


## Upgrade Steps

Follow these steps to upgrade your project to **v1.4.0**.

---

### 1. Upgrade the database server first

Bring the server to 11.7 or newer **before** applying the migrations of this release. With the
Docker stack, bump the `mariadb` image in `packaging/docker/docker-compose-base.yml` and recreate
the container:

```yaml
image: mariadb:11.8
```

---

### 2. Apply the database migrations

The framework-bundled migrations are applied by the project's normal start/seed flow
(`npm run start`, which runs `db:seed` → migrations then seed) or directly with:

```bash
docker exec application php index.php db:migrate
```

New since v1.3.0:

| Migration | Change |
| --------- | ------ |
| `2026-09-07_session-api-key.sql` | Adds `z_logintoken.name`, `is_permanent` and `is_apikey`. |
| `2026-09-08_session-device-and-ip.sql` | Adds `z_logintoken.device`, `reason`, `ip_creation` and `ip_last`. |
| `2026-09-08_uuid.sql` | Adds the `NOT NULL`, unique `uuid` column (native `UUID` type) to `z_user`, `z_role`, `z_organization`, `z_logintoken` and `z_file`. |
| `2026-09-09_session-expires-at.sql` | Adds the nullable `z_logintoken.expires_at` (`TIMESTAMP`), the fixed expiry that overrides the computed session lifetime. |

If you manage schema by hand, the equivalent statements are idempotent (`... IF NOT EXISTS`).

---

### 3. Check code that builds URLs from the root directory

v1.4.0 fixes how a non-empty `rootDirectory` is handled. **With an empty `rootDirectory` (the
default, and what the Docker stack sets through `CONFIG_ROOTDIRECTORY: ""`) nothing changes.** Below
a root directory such as `sub`:

| Value | v1.3.0 | v1.4.0 |
| ----- | ------ | ------ |
| `$opt["root"]`, `$req->getRootFolder()`, `Z.Request.rootPath` | `/sub` | `/sub/` |
| `$opt["absRoot"]`, `$req->getRoot()`, `config("root")` | `https://example.com/sub` | `https://example.com/sub/` |
| `Route::get("/hello")` on `/sub/hello` | no match (compared against the full path) | matches |
| `getUrlParts()` of `/sub/a/b` with `rootDirectory = sub/` | `["b"]` (the slash counted as a segment) | `["a", "b"]` |
| `$res->reroute(["a", "b"])` | 404 (the root directory was missing from the rerouted path) | runs `a/b` |

The only code that needs a change is code that adds its own slash after the root:

```php
// before: /sub//login after the upgrade
$opt["root"] . "/login"
// after
$opt["root"] . "login"
```

Search your project for a slash right after any of the values in the first two rows (`root"] . "/`,
`root ?>/`, `rootPath + "/"`, ...). Routes, `reroute()` calls and `getUrlParts()` need no change
as long as they are written relative to the root directory, which is the only form that worked
before.

#### What was checked

Before the release, the change was checked against eleven existing applications, built on
framework versions from v0.11 to v1.3.0-alpha, by reading their code against the old and the new
behaviour. Each application was checked for:

- every concatenation of `$opt["root"]`, `$opt["absRoot"]`, `getRoot()`, `getRootFolder()`,
  `config("root")` and `Z.Request.rootPath`/`rootHost`/`absRoot` in controllers, models, views,
  mail views and JavaScript
- `Route::` definitions and groups, `reroute()`, `rerouteUrl()`, `getUrlParts()` and direct
  `REQUEST_URI` access
- `.htaccess` (`RewriteBase`), maintenance and login cookie paths, and debug bar usage
- overrides of `email_password_reset` and translation keys under `email.*`
- the effective `rootDirectory` per environment: the INI value, the Docker setup and the
  production and staging deployments

Result:

| Setup found | Applications | Outcome |
| ----------- | ------------ | ------- |
| Deployed with `CONFIG_ROOTDIRECTORY: ""` (every production, staging and Docker environment) | 11 | Identical values, routes and reroutes |
| INI `rootDirectory` without a trailing slash (`sub`, also with spaces) | 5 | Links like `/sublogin` and routes below the root are fixed |
| INI `rootDirectory` with a trailing slash (`sub/`) on v1.2 | 2 | The autorouter no longer strips the controller, links are fixed |
| INI `rootDirectory` with a trailing slash (`sub/`) on v0.11 to v1.0 | 2 | Identical values, those versions already used the value verbatim |
| INI `rootDirectory` empty | 2 | Identical values |
| A slash added after the root (`root . "/path"`) | 0 | Would need the change shown above |
| `Route::` paths that include the root directory | 0 | Would need the root directory removed |

Root directories with spaces (`My App`) behave the same: the router decodes the request path
before stripping the root directory, and `getUrlParts()` counts the encoded segment as one, so both
agree on real requests and on reroutes.

The e2e suite serves the application below `/sub` as well and covers this in
`tests/cypress/e2e/core/root-directory.cy.js` (links, assets and the debug bar, `Route::`
definitions, reroutes, the maintenance cookie, the password reset mail) and
`tests/cypress/e2e/core/request.cy.js` (`getUrlParts()` with one, two and slash-wrapped segments).
